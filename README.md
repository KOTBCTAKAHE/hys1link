# Hys1Link

Неофициальный Android-клиент для серверов **Link Messenger** (`chat.linkmessenger.me`), написанный с нуля на Kotlin и Jetpack Compose.

Link — форк Signal, поэтому клиент говорит на протоколе Signal: libsignal `0.21.1`, та же версия, что в Link 7.4.4. Hys1Link подключается к вашему аккаунту как **связанное устройство** (как Link Desktop): номер и основной телефон остаются прежними, вход по QR-коду.

## Что умеет

- Привязка по QR через `/v1/websocket/provisioning/`; имя устройства шифруется так же, как в Link.
- Сквозное шифрование: Double Ratchet и X3DH (libsignal), sealed sender (корневой ключ Link), sender keys в группах.
- Личные чаты: приём, отправка, ответы, реакции, статусы «отправлено / доставлено / прочитано», индикатор набора.
- Группы V2: zk-учётки, расшифровка названия и списка участников с `stg.linkmessenger.me`, отправка сообщений участникам.
- Синхронизация с телефоном: контакты, прочтения, отправленные с телефона сообщения, заблокированные.
- Профили: имена, «о себе», аватары (AES-GCM по ключу профиля).
- Вложения: автозагрузка фото и голосовых до 25 МБ, остальное по нажатию.
- Фоновое соединение: служба с типом `remoteMessaging`. FCM Link сторонним клиентам недоступен, поэтому держится свой websocket.
- **Соцсеть Link** (`social.linkm.me`):
  - лента: подписки и «Для вас»;
  - рилсы с видео;
  - поиск людей;
  - профили с подпиской и сеткой публикаций, кнопка «Написать»;
  - публикации с комментариями и лайками.
  Вход по токену из `/v1/accounts/refresh`, лента и рилсы приходят в protobuf Wire `clientapi.*`.
- **Импорт файлового бэкапа Link** (`.backup`, пароль из 30 цифр): история чатов, группы с ключами, фото. Ключи шифрования из бэкапа не используются, так как они принадлежат телефону.
- Material 3: четыре акцента (хвоя, залив, слива, янтарь), цвета обоев Android 12+, светлая и тёмная темы.

Пока не умеет: отправлять вложения, публиковать посты и истории, звонки, оплату, создавать группы.

## Установка

1. Скачайте APK из [Releases](../../releases) или из артефактов последнего запуска Actions.
2. Откройте Hys1Link → «Показать QR-код».
3. На телефоне: Link → Настройки → Связанные устройства → «+», отсканируйте код.

Историю, которая была до привязки, можно перенести из файлового бэкапа: Настройки → Перенос истории.

## Сборка

```bash
./gradlew assembleRelease
```

Workflow `.github/workflows/build.yml` собирает APK на каждый пуш в `main` и публикует prerelease. Чтобы обновления ставились поверх, добавьте в Settings → Secrets → Actions:

| Секрет | Значение |
|---|---|
| `SIGNING_KEYSTORE_B64` | `base64 -w0 release.jks` |
| `SIGNING_STORE_PASSWORD` | пароль хранилища |
| `SIGNING_KEY_ALIAS` | алиас ключа |
| `SIGNING_KEY_PASSWORD` | пароль ключа (для PKCS12 тот же) |

Без секретов каждая сборка подписывается одноразовым debug-ключом.

## Как устроено

| Пакет | Что внутри |
|---|---|
| `proto/` | Собственный protobuf-кодек; номера полей сняты с классов Link 7.4.4 |
| `crypto/` | HKDF, шифр привязки, имя устройства, вложения, профили, padding |
| `net/` | OkHttp с доверием к системным CA и CA из `whisper.store` Link (CryptNet), REST, websocket |
| `store/` | SQLite: хранилище протокола Signal, контакты, чаты, сообщения |
| `core/` | Привязка, пре-ключи, приём, отправка (409/410), группы, профили |
| `ui/` | Compose-экраны |

## Замечание о безопасности официального Link

В Link 7.4.4 есть механизм, которого нет в Signal. Сервер через удалённый конфиг `android.vdsSystemAci` назначает «системный» аккаунт. Если от него приходит конверт типа `15` (`LinkDeviceRequest`), основное приложение молча запускает `AutoLinkDeviceJob`. Задача без подтверждения и без уведомления привязывает новое устройство и передаёт ему приватные ключи личности ACI и PNI и ключ профиля. После этого привязанное устройство получает копии всех новых сообщений.

Hys1Link сам такие запросы не выполняет: он вторичное устройство, конверты типа 15 игнорирует и считает их в настройках. Но телефон с официальным Link остаётся уязвим. Периодически проверяйте список связанных устройств.
